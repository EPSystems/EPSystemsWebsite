# Requirements: E&P Systems v2.0 AI Agency

**Defined:** 2026-05-23
**Core Value:** A credible, results-driven AI agency that Bulgarian businesses trust enough to reach out to — discoverable by both search engines and AI answer engines.

**Mode:** RETROACTIVE. Most capabilities below already shipped on `origin/main` after v1.1. v2.0 documents each as a requirement, **verifies it works end-to-end**, and **builds** the items tagged `(GAP)`. Each requirement notes `[shipped → verify]` or `(GAP → build)`.

## v2.0 Requirements

### AI-Agency Repositioning (Phase 8)

- [ ] **REPO-01**: `[shipped → verify]` Site defaults to Bulgarian — `/` redirects to `/bg/`, i18next fallback is `bg`, returning-user preference persists
- [ ] **REPO-02**: `[shipped → verify]` Homepage positions E&P as an AI agency (Hero, Why Us, Results, Testimonials, TrustedBy, Team, CTA), fully bilingual
- [ ] **REPO-03**: `[shipped → verify]` Five AI service pages at `/:lang/services/:slug` (ai-websites, ai-automation, ai-agents, ai-seo, ai-ecommerce), each bilingual with hero, features, process, personas, pricing, FAQ, case-study, and related sections
- [ ] **REPO-04**: `[shipped → verify]` Services hub page at `/:lang/services` lists all five AI pillars
- [ ] **REPO-05**: `[shipped → verify]` Three industry vertical pages at `/:lang/industries/:slug` (insurance, ecommerce, fitness), fully bilingual
- [ ] **REPO-06**: `[shipped → verify]` Navbar exposes AI-pillar dropdown + industries menu, bilingual, with working mobile menu
- [ ] **REPO-07**: `[shipped → verify]` Pricing page at `/:lang/pricing`, bilingual
- [ ] **REPO-08**: `[shipped → verify]` About/Team page at `/:lang/about`, bilingual
- [ ] **REPO-09**: `[shipped → verify]` Dedicated Contact page (`/:lang/contact`) and Privacy Policy page (`/:lang/privacy-policy`), bilingual

### Content & Blog Engine (Phase 9)

- [ ] **BLOG-01**: `[shipped → verify]` MDX blog engine renders posts from `content/blog/` with frontmatter parsed via `src/lib/blog.ts`
- [ ] **BLOG-02**: `[shipped → verify]` Ten posts published as five EN/BG pairs, each with title, excerpt, date, author, category, tags, and readingTime
- [ ] **BLOG-03**: `[shipped → verify]` Blog index at `/:lang/blog` lists posts for the active locale with a working category filter
- [ ] **BLOG-04**: `[shipped → verify]` Post page at `/:lang/blog/:slug` renders MDX with auto-linked headings and breadcrumbs
- [ ] **BLOG-05**: `[shipped → verify]` Each post shows 3 related posts matched by category
- [ ] **BLOG-06**: `[shipped → verify]` `cornerstone` frontmatter flag (8 posts) drives higher sitemap priority
- [ ] **BLOG-07**: `[shipped → verify]` Cornerstone posts contain TL;DR blocks structured for AI-citation extraction
- [ ] **BLOG-08**: `[shipped → verify]` Posts embed contextual hub-links to relevant service/industry pages
- [ ] **BLOG-09**: `[shipped → verify]` `alternateSlug` links EN↔BG post pairs for hreflang
- [ ] **BLOG-10**: `(GAP → build)` Reading time is displayed on post pages (currently captured in frontmatter but not rendered)

### SEO / GEO (Phase 10)

- [ ] **SEO-01**: `[shipped → verify]` Canonical URL injected per page against `https://www.epsystems.org`
- [ ] **SEO-02**: `[shipped → verify]` Hreflang pairs (bg↔en) plus `x-default → /bg/` injected per page
- [ ] **SEO-03**: `[shipped → verify]` `sitemap.xml` generated by `scripts/generate-sitemap.mjs` covering all routes + blog pairs with the documented priority scheme (~40 URLs)
- [ ] **SEO-04**: `[shipped → verify]` `robots.txt` allows crawling and references the sitemap
- [ ] **SEO-05**: `[shipped → verify]` `llms.txt` describes the agency, services, industries, founders, and cornerstone articles with citation guidance for AI crawlers
- [ ] **SEO-06**: `[shipped → verify]` Site-level JSON-LD in `index.html`: Organization/ProfessionalService, WebSite, and Person entities for both founders
- [ ] **SEO-07**: `[shipped → verify]` Per-page JSON-LD: Article on blog posts, BreadcrumbList site-wide, FAQPage on service pages, Service ItemList on homepage
- [ ] **SEO-08**: `[shipped → verify]` Per-page `<title>`, meta description, Open Graph, and Twitter Card tags set via `usePageMeta`/`SEOHead`
- [ ] **SEO-09**: `(GAP → build)` Dedicated Service schema injected on each individual service page (today only the homepage ItemList exists)
- [ ] **SEO-10**: `(GAP → build)` Google Search Console verification meta tag activated (currently commented out in `index.html`)

### Analytics & Consent (Phase 10)

- [ ] **ANLY-01**: `[shipped → verify]` GA4 (`G-ZBK171SEN6`) loads via gtag and reports pageviews
- [ ] **ANLY-02**: `[shipped → verify]` Consent Mode v2 defaults to deny-all and restores stored consent for returning users
- [ ] **ANLY-03**: `[shipped → verify]` Bilingual cookie-consent banner persists the choice and updates GA4 consent state on accept/decline
- [ ] **ANLY-04**: `[shipped → verify]` Vercel Analytics and Speed Insights are active in production

### Form Hardening (Phase 10)

- [ ] **HARD-01**: `(GAP → build)` hCaptcha (or equivalent) added to the contact form on top of the existing honeypot, gated to avoid hurting conversions

## Future Requirements

- **AUTH-PROFILE-01**: Dedicated author profile pages with Person schema
- **BLOG-SEARCH-01**: Full-text blog search (beyond category filter)
- **PROJ-01**: Route and ship the existing Projects/portfolio page (pending client permission)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Backend / CMS | Static SPA; content lives in code/MDX |
| SSR / pre-rendering | SPA + prerendered meta deemed sufficient for now |
| Paid form backend | User requires zero additional cost (Web3Forms free tier) |
| WCAG accessibility audit | Deferred to a later milestone |
| Client logo bar / trust badges | Need client permission |
| Blog full-text search | Category filter sufficient at current post count |
| reCAPTCHA | Hurts conversions/accessibility; hCaptcha preferred |
